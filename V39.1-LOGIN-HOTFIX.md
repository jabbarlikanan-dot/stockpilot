# StockPilot v39.1 — Login compatibility hotfix

## Problem
v39 normalized the entered username to lowercase. Existing D1 databases created by older versions may still have a `users` table without `COLLATE NOCASE`, because `CREATE TABLE IF NOT EXISTS` does not alter an already existing table definition. A legacy account stored as `Krenz` could therefore fail when the login query searched for `krenz`, even when the 4-digit PIN was correct.

## Fix
- Login lookup now explicitly uses `COLLATE NOCASE`.
- Registration duplicate checking is case-insensitive.
- Store/tracking/order owner lookups are case-insensitive.
- Notification recipient lookup is case-insensitive.
- Profile username duplicate checking is case-insensitive.
- Existing PIN hashes are unchanged.
- Existing accounts do not need to be recreated.

## Deploy
Deploy this Worker/frontend version over v39. Existing D1 data should remain untouched.
